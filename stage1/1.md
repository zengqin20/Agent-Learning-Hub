# 用一个 LLM API 完成普通对话

## OpenAI 格式返回内容说明

### 1. 普通响应（非流式）

一次性返回完整内容：

```json
{
  "id": "chatcmpl-123",
  "object": "chat.completion",
  "created": 1677652288,
  "model": "gpt-3.5-turbo-0613",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "你好！我是 AI 助手，有什么可以帮助你的吗？"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 9,
    "completion_tokens": 12,
    "total_tokens": 21
  }
}
```

**关键字段：**

- `choices[0].message.content` - 完整回复内容
- `choices[0].finish_reason` - 结束原因（`stop` 正常结束 / `length` 达到最大长度）
- `usage` - Token 用量统计

---

### 2. 流式响应（SSE 格式）

分多次返回增量内容，实现逐字输出效果：

```
data: {"id":"chatcmpl-123","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"role":"assistant","content":""},"finish_reason":null}]}

data: {"id":"chatcmpl-123","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"content":"你"},"finish_reason":null}]}

data: {"id":"chatcmpl-123","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"content":"好"},"finish_reason":null}]}

data: {"id":"chatcmpl-123","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"content":"！"},"finish_reason":null}]}

data: {"id":"chatcmpl-123","object":"chat.completion.chunk","choices":[{"index":0,"delta":{},"finish_reason":"stop"}]}

data: [DONE]
```

**关键区别：**

- `object` 是 `chat.completion.chunk`（片段）
- 使用 `delta.content` 而不是 `message.content`
- 每个 chunk 只包含**增量内容**（几个字或一个词）
- 最后一个 chunk 的 `delta` 为空，`finish_reason` 为 `"stop"`
- 以 `data: [DONE]` 结束

---

### 3. 错误响应格式

```json
{
  "error": {
    "message": "Invalid API key",
    "type": "invalid_request_error",
    "param": null,
    "code": "invalid_api_key"
  }
}
```

**常见 HTTP 状态码：**

- `401` - 认证失败（API Key 无效）
- `429` - 请求限流（超过配额）
- `500` - 服务器错误

## 多轮对话设计规范

### 核心原理

**OpenAI API 是无状态的** - 每次请求都是独立的，API 不会记住之前的对话。

要实现多轮对话，必须在客户端维护完整的对话历史，并在每次请求时发送全部历史消息。

### 标准实现流程

```python
# 1. 初始化对话历史（包含系统提示）
messages = [
    {"role": "system", "content": "你是一个有帮助的AI助手。"}
]

# 2. 进入对话循环
while True:
    user_input = input("你: ")

    # 3. 添加用户消息到历史
    messages.append({"role": "user", "content": user_input})

    # 4. 发送完整历史给 API
    response = client.chat(messages)

    # 5. 获取 AI 回复
    ai_response = response["choices"][0]["message"]["content"]

    # 6. 将 AI 回复添加到历史（关键步骤！）
    messages.append({"role": "assistant", "content": ai_response})
```

### 消息格式规范

```python
messages = [
    {"role": "system", "content": "系统提示词"},      # 设定 AI 角色和行为（通常只在开头）
    {"role": "user", "content": "用户消息"},           # 用户输入
    {"role": "assistant", "content": "AI 回复"},       # AI 回复（必须保存）
    {"role": "user", "content": "下一轮用户消息"},     # 继续对话
    {"role": "assistant", "content": "AI 再次回复"},   # 保持上下文
    # ... 循环往复
]
```

**三种 role 类型：**

- `system` - 系统指令，设定 AI 的角色、行为准则、回复风格等
- `user` - 用户输入的消息
- `assistant` - AI 的回复（必须保存以维持上下文）

### 对比示例

#### ❌ 错误做法（不保存历史）

```python
# 第一轮
messages = [{"role": "user", "content": "我叫小明"}]
response = client.chat(messages)
# AI: "你好小明！"

# 第二轮（重新开始，没有历史）
messages = [{"role": "user", "content": "我叫什么？"}]
response = client.chat(messages)
# AI: "我不知道你叫什么" - 因为它没有上下文
```

#### ✅ 正确做法（保存完整历史）

```python
messages = []

# 第一轮
messages.append({"role": "user", "content": "我叫小明"})
response = client.chat(messages)
messages.append({"role": "assistant", "content": "你好小明！"})

# 第二轮（包含完整历史）
messages.append({"role": "user", "content": "我叫什么？"})
response = client.chat(messages)
# AI: "你叫小明" - 有完整上下文

# 此时 messages 内容：
# [
#   {"role": "user", "content": "我叫小明"},
#   {"role": "assistant", "content": "你好小明！"},
#   {"role": "user", "content": "我叫什么？"}
# ]
```

### 注意事项

1. **Token 限制** - 对话历史会消耗 Token，需要注意模型的上下文窗口限制（如 gpt-3.5-turbo 是 4096 tokens）

2. **性能优化** - 对话过长时可以考虑：

   - 截断早期对话
   - 使用摘要压缩历史
   - 只保留关键上下文

3. **系统提示** - `system` 角色通常只在初始化时添加一次，不需要每轮重复

4. **错误处理** - 如果 API 调用失败，不应将错误响应添加到历史中

## 参数

### max_tokens

一般模型会有默认值

max_tokens 是 LLM API 中控制生成内容长度的关键参数。

finish_reason: "length" - 达到 max_tokens 限制
finish_reason: "stop" - AI 自然结束
